گزارش واقعی آزمون — فروشگاه همراه ۱.۰.۰

تاریخ: ۱ اکتبر ۲۰۲۶، UTC. این گزارش بین آزمون انجام‌شده، وابستگی به هاست و ادعای تأییدنشده تفاوت می‌گذارد.

WordPress و WooCommerce واقعی اجرا شدند. محصول، تنوع، CSV، سفارش، سبد و حساب آزمایشی از APIها و صفحات اصلی ساخته/پردازش شدند؛ هیچ API ساختگی یا سبد JavaScript نمایشی جای موتور تجارت قرار نگرفت. دادهٔ موقت آزمون در ZIP تحویل نیست.

محیط

وردپرس۷.۱.۲، نصب واقعی از منبع WordPress
ووکامرس۱۱.۱.۲، بستهٔ ساخته‌شده با vendor و assets واقعی. به علت محدودیت دانلود WordPress.org/release-assets در محیط، برای آزمون از mirror عمومی WordpressPluginDirectory/woocommerce استفاده شد. روی هاست خود WooCommerce رسمی نصب کنید؛ این وابستگی داخل ZIP پروژه بازتوزیع نشده است.
PHP اجرایی۸.۳.۳۳ از PHP WASM؛ بررسی دستور زبان همچنین با ۸.۱.۳۴ انجام شد.
پایگاه دادهSQLite Database Integration تیم وردپرس، با لایهٔ ترجمهٔ MySQL. HPOS ووکامرس فعال و APIهای اصلی سفارش اجرا شدند. آزمون پایگاه دادهٔ بومی MySQL/MariaDB در این محیط انجام نشده است.
مرورگرChromium 153 / Playwright؛ عرض‌های ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل. این‌ها مرورگر واقعی با viewportهای آزمون هستند، نه تست روی دستگاه فیزیکی iPhone/Android.

نتایج انجام‌شده

گروهنتیجه و دامنه
دستور زبان و ساختار۲۷ فایل PHP تولیدی با parser واقعی PHP ۸.۱ و ۸.۳؛ هر دو فایل JavaScript با Node؛ پنج CSS با PostCSS؛ JSON قالب و Python بسته‌بندی — موفق.
آزمون API/یکپارچگی PHP۴۱ بررسی موفق: وابستگی واقعی، صفر محصول اولیه، تکرارپذیری آماده‌سازی برگه‌ها، خالی و draft بودن برگه‌های اطلاعات تازه، موبایل/کدپستی، اعتبارسنجی کلاسیک و هوک بلوکی، ارز و تبدیل صرفاً Schema، محصول متغیر، SKU/تنوع/برند/دسته/ویژگی، جلوگیری از نمایش draft/hidden/password، حالت search-only، whitelist طبقه‌بندی، متن شبیه SQL injection، HPOS، یادداشت سفارش، کاهش/بازگشت انبار و CSV بومی.
مرورگر و تجارت واقعی۷۷ بررسی موفق شامل HTTP صفحات، RTL، عدم اسکرول افقی، فیلتر AJAX چندانتخابی، URL قابل اشتراک، قیمت/حراج/انبار/برند/زیرگروه، مرتب‌سازی، جستجوی زنده و کامل، علاقه‌مندی واقعی مرورگر، کشوی فیلتر/منو/Escape، حالت خالی/بی‌تصویر/ناموجود/بدون تخفیف، گالری و Schema، افزودن واقعی به سبد، تغییر تعداد، خرید فوری تنوع بدون پاک کردن سبد، پرداخت واقعی با روش بومی آفلاین COD، رسید سفارش، ثبت‌نام واقعی مشتری، حساب و ورود مدیر و تنظیمات موبایل. خطای JavaScript اجرایی در این مجموعه: صفر.
Store API واقعیCart-Token اصلی، افزودن به سبد، به‌روزرسانی مشتری با ارقام فارسی، نرمال شدن موبایل/کدپستی پیش از schema validation، رد موبایل ایرانی نامعتبر و checkout با COD — موفق؛ سفارش واقعاً در WooCommerce ایجاد شد، نه فقط پیام موفقیت ظاهری.
واکنش‌گرایی و پیش‌روندهپنج عرض اعلام‌شده بدون overflow عمومی کاتالوگ؛ منو/فیلتر موبایل و صفحهٔ حساب/رسید/تنظیمات در ۳۹۰ پیکسل. فرم GET فیلتر با JavaScript خاموش نیز به نتایج واقعی رسید. بزرگ‌نمایی/Lightbox بومی محصول و کلیدهای پیشنهاد جستجو آزمایش شدند.
دسترس‌پذیری خودکارaxe-core با قواعد WCAG A/AA در خانه، فروشگاه، علاقه‌مندی، حساب و پیشنهاد زندهٔ جستجو: صفر تخلف شناسایی‌شده در صفحات بررسی‌شده. این نتیجه ادعای گواهی کامل دسترس‌پذیری یا آزمون همهٔ صفحه‌خوان‌ها نیست.
نصب واقعی ZIPنصب ZIP اصلی با Plugin_Upgrader خود وردپرس موفق بود. پوشهٔ قالب در نصب دورریختنی حذف و cache پاک شد؛ سپس دکمهٔ nonceدارِ مدیریت واقعاً قالب داخلی را از ZIP نصب و فعال کرد. فایل‌های فونت/مجوز پس از نصب موجود بودند. اجرای دوبارهٔ آماده‌سازی برگه‌ها و URL راهنمای داخل افزونه نیز موفق بود.
بسته‌بندییک ریشهٔ افزونهٔ نصب‌پذیر، قالب کامل داخلی، CRC و manifest SHA-256، فایل‌های فونت/مجوز/راهنما و دارایی‌ها بررسی می‌شوند. SQL، پایگاه داده، wp-config، رمز، fixture، CSV، تصویر تجاری نمونه، screenshot و ابزار توسعه از بسته حذف‌اند. قالب هیچ پوشهٔ override از templates ووکامرس ندارد.

حذف دادهٔ موقت

بررسی اولیه، صفر محصول روی نصب تازه را تأیید کرد. آزمون‌ها فقط در پایگاه دادهٔ دورریختنی و با guard مخصوص تست، دادهٔ موقت ایجاد می‌کنند. پاک‌سازی از APIهای محصول/سفارش/کاربر/رسانهٔ WordPress/WooCommerce استفاده می‌کند؛ این کدهای تست داخل افزونهٔ تحویل نیستند. ZIP نصب هیچ پایگاه داده یا دادهٔ تجاری واردشونده‌ای ندارد. نصب پروژه روی فروشگاه قبلی، دادهٔ واقعی موجود را برای «خالی کردن» حذف نمی‌کند.

تأیید پاک‌سازی نهایی: در نصب آزمون، تعداد محصول/تنوع، مشتری، سفارش، رسانهٔ محصول آزمایشی و ردیف نمایهٔ محصول پس از پاک‌سازی همگی صفر شدند. وضعیت خالی واقعی دوباره از مرورگر در دسکتاپ و موبایل بررسی شد.

چه چیزهایی آزمایش یا ادعا نشده است؟

  • تراکنش واقعی درگاه بانکی ایرانی، کلید Merchant، callback بانک و استرداد بانکی؛ به قرارداد و تنظیمات واقعی صاحب فروشگاه وابسته‌اند.
  • تحویل ایمیل واقعی/SMTP و بازیابی رمز از راه صندوق بیرونی؛ در آزمون محلی ارسال ایمیل جلوگیری شد تا پیام آزمایشی برای کسی فرستاده نشود. این مانع ارسال در بستهٔ تولیدی وجود ندارد.
  • سرویس واقعی پست/حمل‌ونقل، پیامک، دستگاه فیزیکی و Safari/Firefox یا مرورگرهای قدیمی.
  • MySQL/MariaDB بومی، بار هم‌زمان تولیدی و benchmark ده‌ها هزار محصول روی هاست شما.
  • تمام افزونه‌های سئو، قیمت‌گذاری، چندزبانه و سازنده‌های تجاری Elementor/WooCommerce؛ مسیر استاندارد محتوا/هوک‌ها حفظ شده، ولی ترکیب شما باید در staging آزمایش شود.
  • فارسی بودن همهٔ رشته‌های JavaScript بلوک‌های جدید صرفاً با ترجمهٔ پشتیبان قدیمی: زبان/ترجمه‌های رسمی WP/Woo باید به‌روز شوند؛ پرداخت کلاسیکِ همراه برای سازگاری ساده‌تر پیشنهاد شده است.

محیط آزمون برای ارتباط HTTPS با WordPress.org محدودیت داشت؛ به‌روزرسانی‌های خود وردپرس در مدیریت، هشدار اتصال بیرونی تولید کردند. این‌ها خطای دستور زبان یا API این افزونه نبودند؛ سلامت ارتباط اینترنت، گواهی‌ها، به‌روزرسانی‌ها و ترجمه‌ها روی هاست واقعی باید بررسی شود.

آزمون پس از نصب روی هاست

پیش از فروش، HTTPS، واحد پول، ارسال، درگاه واقعی، رسید/وضعیت سفارش، انبار، ایمیل، ثبت‌نام، زمان‌بندی و عدم کش عمومی سبد/پرداخت را بررسی کنید. جزئیات مبتدی در راهنمای نصب و مدیریت آمده است. هیچ بستهٔ نرم‌افزاری به‌تنهایی جای این تنظیمات و آزمون محیط واقعی را نمی‌گیرد.
