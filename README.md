# فروشگاه همراه — WordPress / WooCommerce

فروشگاه واقعی فارسی/RTL، بدون دادهٔ نمونه؛ قالب کلاسیک همراه + افزونهٔ سبک. این پروژه یک ماک‌آپ یا برنامهٔ SPA با سبد/پرداخت ساختگی نیست.

## بستهٔ نصب

`artifacts/hamrah-shop-1.0.0.zip` را از **افزونه‌ها ← افزودن ← بارگذاری افزونه** در وردپرس نصب کنید. ابتدا WordPress فارسی و WooCommerce رسمی نصب/فعال باشند. در مدیریت **فروشگاه همراه**، قالب همراه را نصب/فعال و برگه‌ها را آماده کنید. تمام فایل‌های سفارشی لازم در یک ZIP هستند؛ قالب به‌صورت ZIP داخلی نصب می‌شود، نه دانلود خارجی.

- حداقل: WordPress 6.8 / PHP 8.1 / WooCommerce 10.0.
- آزمون واقعی: WordPress 7.1.2 / WooCommerce 11.1.2 / PHP 8.3؛ جزئیات و محدودیت‌ها در گزارش داخل افزونه.
- راهنمای مبتدی: `plugin/hamrah-shop/docs/راهنمای-نصب.html` (همچنین پیوند داخل مدیریت افزونه).
- گزارش آزمون: `plugin/hamrah-shop/docs/گزارش-آزمون.html`.
- ورود مدیر از `/wp-admin/` با حسابی است که **خودتان هنگام نصب وردپرس** ساخته‌اید. هیچ حساب/رمز از پیش ساخته‌شده همراه ZIP نیست.

## مرز داده و مسئولیت

افزونه هیچ محصول، تنوع، سفارش، مشتری، برند، دستهٔ تجاری، مقاله، تصویر کالای نمونه، بنر یا اطلاعات تماس فرضی نمی‌سازد. روی فروشگاه موجود هیچ دادهٔ واقعی پاک/بازنویسی نمی‌شود. راه‌اندازی برگه‌های استاندارد فقط با اقدام صریح مدیر است؛ برگه‌های اطلاعات تازه خالی و پیش‌نویس‌اند. تبدیل اختیاری سبد/پرداخت به کلاسیک، برگه‌های جدید می‌سازد و برگهٔ بلوکی قبلی را حفظ می‌کند.

WordPress/WooCommerce ممکن است نمونه‌های نصب/دستهٔ پیش‌فرض خود را داشته باشند؛ راهنما روش بررسی دستی آن‌ها را توضیح می‌دهد. درگاه بانکی، SMTP، ارسال واقعی، امنیت هاست و انتشار روی دامنهٔ کاربر باید با اطلاعات/سرویس واقعی خود کاربر تنظیم و آزموده شوند. هیچ API یا پرداخت نمایشی جای آن‌ها نیست.

## معماری

- `plugin/hamrah-shop/`: نقطهٔ ورود، تنظیمات، نصب محلی قالب، نمایهٔ جستجوی پیشوندی، فیلتر بومی WooCommerce، ایران، علاقه‌مندی مرورگر و دارایی‌های افزونه.
- `theme/hamrah-shop/`: قالب کامل WP، گوتنبرگ، منو/کشوی موبایل، CSS واکنش‌گرا، فونت محلی و رندر **قالب‌های جاری خود WooCommerce**.
- هیچ کپی از `woocommerce/templates` در قالب وجود ندارد؛ `woocommerce.php` رندر بومی `woocommerce_content()` و هوک‌های اصلی را حفظ می‌کند.
- CRUD محصول/تنوع/قیمت/انبار/سفارش/مشتری/CSV کاملاً استاندارد WooCommerce؛ HPOS و Store API پشتیبانی می‌شوند.
- جدول `{$wpdb->prefix}hamrah_search` فقط نمایهٔ مشتق از محصولات عمومی است، نه جایگزین جدول کسب‌وکار. بازسازی دسته‌ای ۳۰تایی با Action Scheduler/Cron.
- REST افزونه فقط GET دادهٔ عمومیِ محدود و واقعی (`search/products/terms`)؛ نوشتن تجاری از طریق APIهای نمایشی اختراع نشده است.
- قیمت‌های مشتری از getterهای اصلی گرفته می‌شوند؛ پاسخ REST قیمت `no-store` و درخواست کاربر واردشده دارای nonce بومی است.
- علاقه‌مندی تا ۱۰۰ شناسه در مرورگر، بدون ادعای همگام‌سازی حساب. خرید فوری از مسیر واقعی add-to-cart و بدون پاک کردن سبد.
- IRT/IRR قابل انتخاب؛ تغییر واحد پول **قیمت ذخیره‌شده را تبدیل نمی‌کند**. فقط JSON-LD در فروشگاه تومانی برای ISO 4217 به معادل IRR نمایش داده می‌شود.
- داده‌های تماس/منو/محتوا/تصاویر و دسته/برند/ویژگی همگی از WP/Woo؛ هیچ مدل گوشی یا برند ثابت در کاتالوگ نیست.

## ساخت دوبارهٔ ZIP

Python 3 استاندارد کافی است؛ Node/PHP برای نصب روی هاست لازم نیستند (هاست WordPress خود PHP دارد).

```sh
python3 scripts/build.py
python3 scripts/check-package.py artifacts/hamrah-shop-1.0.0.zip
```

سازنده مسیرهای تولیدی را سفیدفهرست می‌کند، ZIP قالب داخلی را از `theme/hamrah-shop` بازسازی و manifest SHA-256 می‌نویسد. پایگاه داده، نصب آزمایشی، ابزار، fixture، screenshot، CSV، رمز و `.git` در بسته نیستند. `artifacts/` و `.cache/` در Git نادیده گرفته می‌شوند؛ ZIP داخلی کوچکِ قالب بخشی از منبع توزیع افزونه است.

## آزمون توسعه

**فقط در یک نصب دورریختنی؛ هرگز روی فروشگاه واقعی اجرا نشود.** آزمون‌ها با APIهای اصلی محصول/تنوع/سفارش/CSV کار می‌کنند و برای سنجش، دادهٔ موقت ایجاد می‌کنند؛ این داده در ZIP توزیع نیست.

- `tests/integration.php`: WordPress/WooCommerce واقعی، وابستگی، راه‌اندازی تکرارپذیر، draft، موبایل/کدپستی، محدودیت دادهٔ عمومی، جستجوی SKU/ویژگی/برند، HPOS، انبار و CSV.
- `tests/browser.mjs`: Playwright/Chromium، URL/AJAX/RTL/موبایل، سبد، تنوع، پرداخت بومی آفلاین، حساب واقعی و مدیریت.
- `tests/store-api.mjs`: Cart-Token و Store API واقعی با ارقام فارسی؛ پرداخت COD فقط در نصب تست فعال می‌شود.
- `scripts/lint.mjs`: PHP WASM نسخه‌های ۸.۱ و ۸.۳، JS و CSS.

ابزارهای توسعه در `.cache/tools` نصب شده‌اند؛ آن‌ها پیش‌نیاز هاست نیستند. نصب آزمایش از WordPress/WooCommerce واقعی و SQLite Database Integration تیم وردپرس استفاده می‌کند؛ آزمون MySQL/MariaDB بومی، بانک واقعی، تحویل ایمیل و افزونه‌های تجاریِ دلخواه در این محیط انجام نشده‌اند. جزئیات دقیق در گزارش تحویل است. fixtureها پس از آزمون پاک می‌شوند.
